# μ(sic) Behavior Contract {行為契約}

本契約明文規範 μ(sic) 系統中所有 Behavior Metrics {行為指標} 的資料型別、數值範圍（Scale）、資料庫儲存標準（Invariants）及前端呈現對應關係。

所有對行為指標的計算、測試與儲存，均必須嚴格遵守此合約。

---

## 1. 指標契約定義 (Metric Invariants)

| 指標名稱 (Metric Name) | 資料型別 (Type) | 數值範圍 (Range) | 單位與意義 (Unit & Semantics) | 前端呈現格式 (Presentation) |
| :--- | :--- | :--- | :--- | :--- |
| **Novelty Index** {原創性指數} | `Float` | `0.0 ~ 1.0` | 新發現曲目數占總播放曲目數的比率。 | `0% ~ 100%` (例如 `0.83` 顯示為 `83%`) |
| **Repeat Rate** {重聽率} | `Float` | `0.0 ~ 1.0` | 播放次數 $\ge 3$ 次的曲目播放量占總播放量的比率。 | `0% ~ 100%` (例如 `0.45` 顯示為 `45%`) |
| **Genre Diversity** {曲風多樣性} | `Float` | `0.0 ~ 1.0` | 香農商（Shannon Entropy）常態化值（最大 Entropy 設為 5.0）。 | `0% ~ 100%` (例如 `0.72` 顯示為 `72%`) |
| **Session Length** {單次聆聽時長} | `Float` | `0.0 ~ 240.0` | 每次連續聆聽 Session 的平均分鐘數（上限 4 小時以剔除掛機）。 | `X.X 分鐘` 或 `X 分 X 秒` |
| **Peak Listening Hour** {巔峰聆聽時段} | `Int` | `0 ~ 23` | 本地時間連續 2 小時巔峰聆聽時段的起點小時。 | `HH:00 ~ HH:00` (例如 `22` 顯示為 `22:00 ~ 00:00`) |
| **Confidence** {信賴度} | `Float` | `0.0 ~ 1.0` | 推論之可靠分數。基於覆蓋率、一致性與近距性三者乘積。 | `0% ~ 100%` (例如 `0.95` 顯示為 `95%`) |

## 2. 開發設計規範 (Engineering Principles)

1. **資料庫儲存原則**：
   - 資料庫（如 `BehaviorSnapshot` 資料表）中儲存的必須是 **原始數值（Raw Float/Int）**。
   - **絕對禁止** 在資料庫中儲存已乘以 100 的百分比整數（如 `83`）或格式化後的字串（如 `"83%"` 或 `"22:00"`）。
2. **職責分離**：
   - `Behavioral Engine` {行為引擎} 僅負責數學計算，並輸出符合本契約之數值。
   - UI / Presentation 視圖層負責在渲染時將 `0.8324` 轉換為使用者易讀的 `83%`，或轉換為本地時區時間區間。
3. **時間窗口（Window）支援**：
   - 所有的行為指標皆必須傳入 `window` 參數（支援 `"7d"`, `"30d"`, `"90d"`, `"all-time"`）。
   - 計算歷史資料時，時間起點應由 `window` 倒推（例如 7d 即為當前時間往前 7 天，all-time 則為全部歷史）。
