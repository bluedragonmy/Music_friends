# μ(sic) Domain Model {網域模型}

本文件定義 μ(sic) 核心概念的語意與名詞定義。為確保系統開發、演算法計算與 AI 理解的一致性，團隊與模型應嚴格遵守此名詞系統。

---

## 1. 數據流動概念 (Data Stream Concept)
在系統內部與使用者體驗的設計中，數據與認知的流動採用單向流動架構，並以 Machine {機器} 與 Human {人類} 作為分界：

`Collect` {收集} -> `Observe` {觀察} -> `Measure` {測量} -> `Infer` {推論}
─────────────────── Machine ↑ / Human ↓ ───────────────────
`Present` {呈現} -> `Understand` {理解}（使用者） -> `Reflect` {反思}

1. **Collect** {收集}：透過 Spotify API {Spotify 應用程式介面} 獲取並儲存使用者的原始聽歌日誌與曲目聲學屬性。
2. **Observe** {觀察}：對收集到的原始資料進行基礎統計與整理（例如總播放次數、播放天數），但不進行指標權重計算。
3. **Measure** {測量}：運用數學公式算出具備科學根據的 Metrics {指標}，如新穎度指數或重聽率。
4. **Infer** {推論}：將 Measure {測量} 的數值指標透過規則圖推論出身份特徵，但不做過度的人類性格詮釋。
5. **Present** {呈現}：將推論出的客觀數據與觀察以乾淨、留白的方式呈現給使用者。
6. **Understand** {理解}：使用者自行觀看呈現的資訊，產生屬於自己的理解與體會（AI 不會真正「理解」，「理解」是使用者的工作）。
7. **Reflect** {反思}：藉由具備引導性的音樂性問題，促使使用者進一步自我反思。

## 2. 核心名詞定義與對比 (Core Vocabulary)

### 2.1 Listening History {聆聽歷史} vs Listening Session {聆聽時段}
* **Listening History** {聆聽歷史}：
  - **定義**：使用者聽歌行為的完整時間序列累積。這是一個無間斷的、按時間順序排列的事件集合。
  - **用途**：用於計算長期偏好、多樣性或整體聽歌量。
* **Listening Session** {聆聽時段 / 聆聽單元}：
  - **定義**：使用者一次連續不間斷的聽歌活動區間。當兩次聽歌事件的間隔時間超過設定閾值（例如 30 分鐘）時，系統將視為前一 Session 已結束，新一 Session 已開始。
  - **用途**：用於分析單次聆聽專注力、聆聽場景（例如通勤、深夜專注）與 Session Length {單次聆聽時長}。

### 2.2 Track {曲目} vs Listening Event {聆聽事件}
* **Track** {曲目}：
  - **定義**：音樂目錄中的靜態實體，包含 `Title` {歌名}、`Artist` {演出者}、`Album` {專輯}、`Duration` {歌曲時長}、`Popularity` {熱門度} 與 `AudioFeature` {聲學屬性}。
  - **特點**：在資料庫中全系統唯一，只記錄曲目本身屬性，與特定使用者的聽歌行為無關。
* **Listening Event** {聆聽事件} (於資料庫中為 `SyncLog` {同步日誌})：
  - **定義**：某個特定 User {使用者} 在特定 `PlayedAt` {播放時間戳記} 播放了某個 `Track` {曲目} 的行為日誌，並附帶 `ListenDurationMs` {實際聆聽毫秒數}。
  - **特點**：屬於動態的日誌資料。

### 2.3 Artist {演出者} vs Genre {曲風}
* **Artist** {演出者}：
  - **定義**：曲目的創作者或演唱者。
* **Genre** {曲風}：
  - **定義**：音樂的風格流派。
  - **注意**：Spotify API 中曲風（Genres）是綁定在 `Artist` {演出者} 身上，而非直接綁定在 `Track` {曲目}。因此在 μ(sic) 中，一首 Track 的 Genre 是由其 primary artist {主要演出者} 的曲風標籤群組聚合衍生而來。

### 2.4 Novelty {原創性 / 新穎度} vs Diversity {多樣性}
* **Novelty** {原創性}：
  - **定義**：使用者在特定時間段內，探索自己「從未聽過」的全新音樂（新歌手、新曲目）的程度。
  - **公式基礎**：新曲目/新歌手在總播放次數中的占比。
* **Diversity** {多樣性}：
  - **定義**：使用者在給定時間段內，聽歌分布的分散程度（混亂度/熵值），即使這些歌手或曲風是使用者以前聽過的。
  - **公式基礎**：資訊熵算法 (Entropy)，計算聽歌分布是集中在少數幾位歌手，還是廣泛分散在眾多歌手。

### 2.5 Identity {身份} vs Behavior {行為}
* **Identity** {身份 / 人格}：
  - **定義**：基於長期數據 Measure {測量} 後所得出的綜合特徵解釋（例如 Explorer {探索者}、Collector {收集者}）。
  - **特點**：高階詮釋，帶有情緒感知與自我認同的描述。
* **Behavior** {行為}：
  - **定義**：使用者的直接客觀物理行為（如切歌、重複播放同一首歌、在特定時間播放）。
  - **特點**：最底層的可觀察事實，是 Identity 的唯一證據來源。
